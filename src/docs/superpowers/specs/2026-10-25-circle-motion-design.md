# 원 주행 노드 설계 (`ros2 run lekiwi_motion circle 0.5`)

> **보류 (2026-10-25):** 사용자가 라즈베리파이에서 노드를 빌드하지 않고 대시보드에서 계산하는 방식으로 바꿨다.
> 새 설계: `lekiwi_web_operator/docs/superpowers/specs/2026-10-25-motion-planner-page-design.md`.
> 이 문서의 측정 사실과 안전 원칙은 새 설계가 그대로 가져갔다. 로봇 안에서 도는 제어가 필요해지면 이 안으로 돌아온다.

2026-10-25. 승인: 사용자 (대화에서 설계를 읽고 "구현 진행"으로 승인).

## 의도

LeKiwi가 **반지름 r 의 원을 센서(odom · IMU)로 확인하며 돈다**. 영상 촬영용으로 쓴다.
지금까지의 `lekiwi-mobile-base/play_motion.py`는 같은 속도 명령을 열린 루프로 보내서, 로봇마다
다른 원을 그렸다 (같은 도메인의 다른 로봇과 섞이는 문제는 따로 고쳤다). 이 노드는 실제 움직임을 보고 원 위로 되돌린다.

## 목표 · 비목표 · 반목표

목표
- `ros2 run lekiwi_motion circle 0.5` 한 줄로 반지름 0.5 m 원을 계속 돈다 (`--laps N`이면 N바퀴 뒤 멈춘다).
- 로봇 4대에서 같은 원에 가깝다. 목표(추정): 3바퀴 이상에서 `odom` 반지름이 r ± 0.03 m, 출발점 복귀 오차 0.05 m 이내.
- 바퀴마다 평균 반지름 · 편차 · 복귀 오차를 출력하고 CSV 로 남긴다 (`--log`). 로봇끼리 비교하는 지표다.

비목표: 임의 경로 추종, 장애물 회피, 라이다 위치 보정, 웹 UI 연동 (나중에 같은 노드를 붙일 수 있다), 팔.

반목표 (이러면 기술적으로 돌아가도 실패)
- 센서가 끊기거나 거짓인데 폭주한다.
- 닫힌 루프인 척하면서 센서가 없을 때 조용히 열린 루프로 돈다.
- 다른 로봇의 `cmd_vel` · 토크 · ready 와 섞인다.

## 확인된 사실 (lekiwi04 실측, 2026-10-25)

- 토픽: `odom` (`nav_msgs/Odometry`, 50.0 Hz, 엔코더 기반), `lekiwi/sensor/offset_imu` (`sensor_msgs/Imu`, 100.1 Hz, best-effort, 자이로 바이어스만 제거), `cmd_vel` (`geometry_msgs/Twist`), 토크 서비스 `lekiwi/motor/power`, 준비 토픽 `lekiwi/motor/ready`.
- 베이스 컨트롤러 상한: 0.23 m/s, 1.53 rad/s, 바퀴 상한 4.6 rad/s. `cmd_vel` 이 0.3 s 끊기면 바퀴 0. 상한을 넘는 명령은 같은 비율로 줄인다 (반지름은 유지).
- IMU: 정지 때 자이로 바이어스 |평균| ≤ 0.0003 rad/s, 잡음 σ ≈ 0.0008 rad/s. 가속도 z = +10.3 m/s² (위쪽, 눈금은 5 % 큼 → 가속도는 쓰지 않는다).
- 자이로 z 부호: 반시계 + (`odom` yaw 와 같다).
- `odom` 거리 정확도: 2.000 m 줄자 대비 1.9717 m (-1.4 %). `encoder_odom_scale` 1.0 유지.
- 회전: 제자리 회전에서 자이로/`odom` = 1.004 (느림), 1.035 (빠르고 섞임).
- **열린 점:** 직진 중 자이로 적분이 `odom` yaw 와 어긋난다. 전진 +0.09~0.11 °/s, 후진 -0.15 °/s (그때 `odom` 은 0.1° 이내).
  진동 때문에 바이어스가 바뀐 것인지, 몸체가 실제로 조금 도는데 `odom` 이 못 보는 것인지 모른다. 그래서 방향각을 어느 쪽에 얼마나 맡길지는 로봇에서 `use_imu_yaw` 로 비교해 정한다.
- 정지 중에도 `odom` 위치가 15초에 2.4 cm 흐른 적이 있다 (토크 켠 상태). 이동 중에는 영향이 작다.
- 4대 모두 `ROS_DOMAIN_ID` 가 달라야 한다 (41, 22, 43, 44). 같으면 `cmd_vel` · 토크 서비스 · ready 가 섞인다.
- 고장 고정 상태에서는 `power true` 가 거절된다. `power false` 가 성공해야 풀린다.
- 로봇의 `~/lekiwi_ws/src` 는 git 저장소가 아니다. 파일을 복사해 로봇에서 `colcon build` 한다.

## 결정

- 패키지 `lekiwi_motion` (`ament_python`, `lekiwi_ws/src/lekiwi_motion`), 실행파일 `circle`. 인자: `radius` (위치 인자, m), `--speed` (기본 0.12 m/s), `--cw`, `--laps`, `--delay` (출발 전 카운트다운, 기본 5 s), `--log`, `--no-imu-yaw`.
- 기본 속도 0.12 m/s (바퀴 상한의 약 60 %). 최대 속도에서는 보정할 여유가 없다. `--speed` 상한은 베이스 컨트롤러 상한과 바퀴 상한 안으로 막는다.
- 제어: 출발 자세에서 왼쪽(`--cw` 면 오른쪽)으로 r 떨어진 점을 중심으로 잡고, 반지름 오차와 접선 방향 오차로 `wz` 를 보정한다 (`wz = v/r + 보정`). 앞을 보고 도는 방식만 한다.
- 위치는 `odom` 의 몸체 속도에서, 방향은 IMU 자이로 적분을 `odom` yaw 쪽으로 천천히 끌어당기는 보완 필터로 추정한다. `--no-imu-yaw` 면 `odom` yaw 만 쓴다.
- 안전 (모두 필수):
  - 시작 전 `cmd_vel` 을 받는 베이스 컨트롤러가 정확히 1개여야 한다. 아니면 거부한다. 다른 발행자(웹 게이트웨이 제외)가 있어도 거부한다.
  - 고장 고정이면 `power false → true` 로 풀고 다시 켠다. 안 풀리면 오류로 끝낸다.
  - 가속 제한 (선 0.4 m/s², 회전 2.4 rad/s²). Ctrl+C · SIGTERM · SIGHUP 은 감속 → 0 → 토크 끄기.
  - `odom` 또는 IMU 가 0.2 s 넘게 끊기면 멈춘다. `ready=false` 가 되면 멈춘다 (도메인이 분리된 뒤의 자기 로봇 값).
  - 반지름 오차나 방향 오차가 한도를 계속 넘거나 (폭주), IMU 와 `odom` 의 회전 속도가 크게 어긋나면 멈춘다. 자이로 z 부호가 `odom` 과 반대면 시작을 거부한다.
  - 토픽 이름은 상대 이름으로 쓴다 (`cmd_vel`, `odom`). 장치 경로 · 절대 경로를 코드에 박지 않는다.
- 토크 켜기 · `cmd_vel` 발행 · 정리는 기존 `lekiwi_teleop` 의 `RosMotorEndpoint` / `cleanup_session` 을 쓴다 (`exec_depend`). 로봇에 이미 설치돼 있다.
- 제어 로직(기하 · 필터 · 램프 · 감시)은 ROS 없이 시험되는 순수 모듈로 두고, ROS 노드는 얇게 연결한다.

## 빌더에게 맡기는 것

- 제어 식과 이득 값, 보완 필터 시간 상수, 정지 한도(폭주 · 불일치)의 숫자. 단, 아래 시뮬레이션으로 근거를 보인다.
- 모듈 · 함수 쪼개기, CSV 열 구성, 출력 문구 (한국어).

## 검증

1. 순수 로직 단위 시험 (`pytest`, ROS 없이).
2. 시뮬레이션: 속도 ±15 %, 미끄러짐, 센서 잡음, 지연을 준 가짜 로봇 4대가 거의 같은 원을 그리는지 (반지름 · 복귀 오차 수치로).
3. 가짜 ROS 로봇(별도 도메인, localhost 전용)으로 전체 노드 시험: 정상 · 고장 고정 · 베이스 2개 · 센서 끊김 · Ctrl+C.
4. lekiwi04 실물: 정지 상태 읽기 확인 → 사용자가 옆에서 지켜보는 가운데 낮은 `--speed` 로 시작.

## 빌더 검토에서 정한 것 (작성자의 판단, 사용자가 문서를 읽고 고칠 수 있다)

- **시뮬레이션은 참 자세로 판정한다.** 제어기는 `odom`(엔코더)과 자이로만 본다. 시험용 로봇 모델에 넣는 수치:
  모터 속도 배율 ±15 %, `odom` 거리 배율 ±3 % (실측 -1.4 %), 요 미끄러짐 ±0.15 °/s (`odom` 이 못 봄), `odom` 지연 0.15 s,
  위치 잡음 σ 1 mm, 정지 중 흐름 2.4 cm / 15 s. `odom` 배율 오차는 제어기에 안 보이는 반지름 오차가 된다:
  ±3 % 면 r = 0.5 m 에서 ±1.5 cm 라서 목표(± 3 cm) 안이다. 시험이 목표를 못 맞추면 이득을 다시 맞추거나,
  안 되는 이유를 수치로 보고한다 (목표를 말없이 느슨하게 하지 않는다).
- **"3바퀴 이상"의 뜻:** 4바퀴를 돌려 **2~4바퀴째**로 잰다. 첫 바퀴는 진입 과도 구간이다.
- **IMU 는 어떤 모드에서도 필수다** (살아 있음 · `odom` 과의 회전 속도 비교 · 부호 검사). `--no-imu-yaw` 는 방향각에 IMU 를
  쓰지 않을 뿐 감시는 계속한다. IMU 가 없는 로봇은 이 노드를 못 쓴다 (조용히 열린 루프로 돌지 않는다는 반목표).
- **자이로 부호 검사는 출발 뒤에 한다.** 램프 동안 `odom` yaw 가 5° 쌓였을 때 자이로 적분과 부호가 반대면 감속 정지한다.
  시험 회전을 따로 넣지 않는다.
- `--no-imu-yaw` 는 ROS 파라미터 `use_imu_yaw` (기본 true) 를 false 로 두는 CLI 스위치다. 같은 스위치다.
- **기본은 융합 켜짐.** 로그에는 `odom` 자세 · `odom` yaw · 자이로 적분 yaw · 융합 yaw 를 모두 남긴다.
  어느 yaw 가 맞는지는 시뮬레이션으로 정할 수 없고, 사용자가 로봇에서 바닥 표시로 판단한다.
- 위치는 `odom` 속도(twist)가 아니라 **자세(pose) 증분**에서 구한다. twist 는 엔코더 창 때문에 지연될 수 있다 (구현 중 확인).

## 배포

로봇은 git 저장소가 아니므로 `lekiwi_motion` 디렉터리를 복사하고 로봇에서 `colcon build --symlink-install --packages-select lekiwi_motion` 을 한다 (빌드는 가상환경이 섞이지 않게 `env -i` 로, 인수인계 문서 §2). 배포 · 재시작은 그때마다 사용자에게 먼저 묻는다.
